## Prompt Enhancement 已按官方接上（提交 a0d40cb）

**PE 和「AI 向导」不是一回事，官方用的也不是同一个模型**（这条最容易混）：
- PE → QI2 自己的 CLIP = **Qwen3-VL 8B**（`character_creator_v2.py:1293`，走 `TextGenerate`）
- Wizard / Analyze Captions → Qwen3.5-4B **gguf**（`:1832` / `character_cloner.py:292`）

→ 所以 **PE 不需要 gguf**：我们 `engine.py:478` 的 `Qwen3VLForConditionalGeneration`
就是同一个东西，零新权重。用户选 gguf 那次决定只影响 Wizard/Analyze。

实现：`workflows/qwen_text.py`（生成调用）+ `charactergen.enhance_character_prompt`，
按官方 `generate_creator_qi2_prompt`（:1271-1317）整条：切掉 LoRA triggers 行再送 PE
（:1285）→ PE → 补回透明底（:1308）→ **PE 之后**追加风格参考（:1315）→ 补 LoRA（:1316）。
参数照抄 :159-174（2048/0.3/64/0.95/0.05/1.05，thinking=False）。

**踩坑（测试抓出来的）**：用"改写结果 != request"判断改写成功会**假阳性**——
`.strip()` 去掉尾空格后就不等了（"Additional details: " 这种结尾带空格的行）。
改成 `_qi2_rewritten_prompt` 失败时返回空串，由调用方统一退回原文。

⚠️ **待办（用户说先记着）**：PE 要常驻 GPU 跑自回归解码，而管线是"编码完就挪走"
（`engine.py:439`，两块 fp8 常驻 15.5GB 已压线）→ 24GB 上跟 transformer 抢；
8B 解码 2048 token 也不快。待办：量真实显存/耗时再定默认值与"PE 完立刻卸载"策略。
