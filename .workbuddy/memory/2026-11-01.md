## Prompt Enhancement 已按官方接上（提交 a0d40cb）

**PE 和「AI 向导」不是一回事，官方用的也不是同一个模型**（这条最容易混）：
- PE → QI2 自己的 CLIP = **Qwen3-VL 8B**（`character_creator_v2.py:1293`，走 `TextGenerate`）
- Wizard / Analyze Captions → Qwen3.5-4B **gguf**（`:1832` / `character_cloner.py:292`）

→ 所以 **PE 不需要 gguf**：我们 `engine.py:478` 的 `Qwen3VLForConditionalGeneration`
就是同一个东西，零新权重。用户选 gguf 那次决定只影响 Wizard/Analyze。

实现：`workflows/qwen_text.py`（生成调用）+ `charactergen.enhance_character_prompt`，
按官方 `generate_creator_qi2_prompt`（:1271-1317）整条：切掉 LoRA triggers 行再送 PE
（:1285）→ PE → 补回透明底（:1308）→ **PE 之后**追加风格参考（:1315）→ 补 LoRA（:1316）。
参数照抄 :159-174（2048/0.3/64/0.95/0.05/1.05，thinking=False）。

**踩坑（测试抓出来的）**：用"改写结果 != request"判断改写成功会**假阳性**——
`.strip()` 去掉尾空格后就不等了（"Additional details: " 这种结尾带空格的行）。
改成 `_qi2_rewritten_prompt` 失败时返回空串，由调用方统一退回原文。

⚠️ **待办（用户说先记着）**：PE 要常驻 GPU 跑自回归解码，而管线是"编码完就挪走"
（`engine.py:439`，两块 fp8 常驻 15.5GB 已压线）→ 24GB 上跟 transformer 抢；
8B 解码 2048 token 也不快。待办：量真实显存/耗时再定默认值与"PE 完立刻卸载"策略。

## 表情贴边重抠 + 内衣底图 + 图集导出（第三轮）

用户要的三项。前两项照官方补，第三项是自己补的工程环节。

### 1. 表情 alpha 精修（官方第二段，之前缺）

官方是**两段**：贴回（做了）+ `_run_emotion_bg_remove`（没做）。缺的表现是
"该透明的地方贴着一块幕布色脏斑"。

- `detailer_region_mask`（`:3683-3706`）：max_pool 膨胀 8 + avg_pool 羽化 4，
  **取 max(mask, softened)** —— 单纯替换成平滑结果会把边缘从 1 拉到 0.5 以下，
  重抠不到边。
- `merge_emotion_rgba`（`:3707-3748`）：**预乘空间** lerp。straight 空间直接混会
  让半透明发梢偏亮（实测红通道 50 vs 正确的 20）。

**关键认知**：QI2 分支没有 FaceDetailer，`detailer_mask` 就是**裁切框矩形**
（`:1692-1698`）。所以"贴边"= 框碰到透明处。

## LoRA「加载报错」排查 + 强度 bug 修复（commit f1869e7）

用户报「挂 LoRA 报错，之前内存超了」，补充「先修强度那个 bug」。

### 排查结论：挂载本身不报错

实测（真机 RTX4090 + cpu offload）：
- `models/lora/` 11 个 `.safetensors` **全是 diffusers 原生格式**（`transformer.`
  前缀 + `lora.down/up.weight`），`available_loras()` 能全列出来。
- 单个挂载、多 LoRA 同时挂（含 640MB 的 rank-128 大 LoRA）、叠加快速模式、
  挂载后 `generate.txt2img` 实际生成 —— **全都不报错**。
- 挂 3 个 LoRA 后 `alloc=0G reserved=0G`：**挂 LoRA 不占 GPU 显存**（cpu offload）。

### 真 bug ①：多 LoRA 强度滑块

`Sidebar.tsx` 强度滑块只绑 `activeLoras[0].scale`，拖动却
`onLorasChange(activeLoras.map(...))` 把**所有** LoRA 强度设成同一个值。
改成每个 LoRA 行各自一个滑块（勾选后展开），拖动只改自己那条。

### 真 bug ②：CPU 内存 OOM 没被兜底

`_infer` 只捕获 `torch.OutOfMemoryError`（CUDA 专用）。cpu offload 模式下权重
每次前向都要反量化搬一次，挂大 LoRA 后 CPU 侧峰值叠加，OOM 以 **CPU 内存耗尽**
（`RuntimeError: out of memory / alloc_cpu`）出现，之前**直接 failed 不兜底**。
现在 `_infer` 同时兜 CPU OOM（按消息匹配），走同一条「gc + empty_cache +
清缓存 + 缩 3/4」降档链。

### 记住
- Qwen 走 **cpu offload**（`MEOW_QWEN_OFFLOAD` 默认开），加载完 `allocated=0`，
  别拿它判断「加载没生效」。（MEMORY.md 度量约定里已有这条）
- LoRA 加载报错排查先别猜格式/rank —— 先跑 `available_loras()` 看列没列出来，
  再真机挂一遍；挂载这层基本不会错，错在生成时的内存。

## 人偶姿势：机位从 8 档放开成任意角度（commit 817180d）

用户反馈「人偶姿势不能任意切换视角，角色迁移效果很差」。

### 根因
官方 VNCCS PoseStudio 的机位是**连续任意角度**：`core.js` 的
`updateCaptureCamera(..., yawDeg, ...)` 直接 `degToRad(Number(yawDeg))`，
不取整。`capture(width,height,zoom,bg,ox,oy,yawDeg,pitchDeg)` 第 7 参数就是
朝向，任意值都行。我们的 `entry.js` 的 `setYaw`/`renderOut` 链路本就透传
任意角度给官方 `capture`，**之前只是宿主页 `PoseStudio.tsx` 用 `YAWS`

角色迁移贴合度差的直接原因：姿态 LoRA 按连续机位训练，动作参考图只有
45° 步进时机位对不上（30°/60° 这类角度拿不到）。

### 改法
朝向下拉（8 常用预设）下加一条「机位微调」连续滑块 0~359° 步进 1°，
选预设后还能微调。8 档预设保留当快捷。

### 记住
- 人偶**朝向 = 导出机位**（`setYaw` → `capture` 的 yawDeg），**任意角度合法**；
  画布里的右键轨道旋转只是「检查视图」，不影响导出（官方同理，capture framing
  与导航相机分离）。
- 官方 `capture` 签名：`capture(width,height,zoom,bgColor,offsetX,offsetY,yawDeg,pitchDeg,options)`。

## 人偶「相机视角」：所见即所得 + 右键换机位（commit 39d5918）

用户接着反馈：机位滑块「看不到效果」，因为画布里的视角（右键轨道旋转的
检查相机）不跟着机位走。要求加「相机视角」切换 + 右键也能换视角，
并参考行业成熟产品（Blender/Unity 的相机模型）。

### 交互模型（对齐 Blender/Unity）

- 官方 `snapToCaptureCamera` 把**导航相机对齐到 capture 机位**，但不复制
  fov/aspect（capture frame 以盒子显示在 3D 空间）。这就是「相机视角」的核心。
- **相机视角 ON**：拖机位滑块人偶实时转；右键拖动直接反算成 yaw
  （`yaw = atan2(dx,dz)`）更新机位，所见即所得。
- **相机视角 OFF**：自由检查视角，右键不影响导出机位。

### 实现要点（entry.js / PoseStudio.tsx）

- `snapCamera`：`v.snapToCaptureCamera(w,h,1,0,0,yaw,0)`
- `yawFromCamera`：`atan2(camera.x-orbit.x, camera.z-orbit.z)` 反算 yaw
- `bindFollow`：orbit 的 `change` 事件 + rAF 合帧节流（change 高频触发）
- 子窗推回 `{type:'pose', yaw, camera:true}`，宿主 `onYaw` 同步

### 真机验证（无头 Edge + SwiftShader）
- yaw=30（非 45 倍数）getPose 回传 30 正确保持
- **yaw=0 vs 90 导出的 PNG 不同**（DIFF_SAME=false），机位真实生效

### 记住
- 官方 `capture(width,height,zoom,bg,ox,oy,yawDeg,pitchDeg)` 第 7 参数 yawDeg
  **任意角度合法**；`snapToCaptureCamera` 同签名，把导航相机对齐过去。
- orbit 有 `change` 事件（每次旋转/平移触发），可监听反算朝向。
- 改了 entry.js 要重新 `npm run build` 同步到 dist（dist 被 git 忽略，是构建产物）。

## 人偶导出改为所见即所得 + 彻底移除方向词（commit e22ebdf）

用户连续指出两个真问题，逐层查证后修掉。这两个都值得记下来。

### ① 导出被「朝向」锁死 → 官方 viewport capture

官方 `core.js` 的 `capture()` 第 5728 行：
`const camera = options.viewport ? this.camera : this.captureCamera`。
默认用 `captureCamera`（由 yawDeg 驱动的固定相机），`options.viewport=true`
才用当前导航相机 `this.camera`（所见即所得）。

我们之前 export 一直走 `capture(..., yawDeg)`（captureCamera），所以导出被
「朝向」值锁死。改成 `capture(..., { viewport: true })` 后，右键转到哪导出就是哪。

**「朝向」/「机位」从此只是快捷对齐**（snapToCaptureCamera 摆到标准角度），
导出永远跟当前视角。「相机视角」开关删掉了——不再需要（没有检查/导出相机分离）。

### ② 文字方向词压过姿势 → 真 bug + 彻底移除

**真 bug**：`App.tsx` 的「用人偶图就不补方向词」保护读 `upNode.mannequin.path`，
但 `mannequin` 字段早随线框骨架删了（人偶图现在只挂 `image` 字段）。所以保护
恒失效，选个非正面朝向方向词照样写进去压姿势。

**更深结论**（docs/VNCCS-REAL.md 实测）：任何方向词（哪怕弱化说法）都会压姿势。
官方 VNCCS 从不写方向词——方向长在渲染的相机机位里。

**做法**：彻底移除方向词写入，角色迁移永远不塞 front/side/back。朝向下拉
改成禁用的「由图决定」+ 提示「要换视角回人偶编辑器转」。

### 记住（跨会话都要用）
- 人偶**导出 = viewport capture（当前视角，所见即所得）**，不是 yaw 驱动的 captureCamera。
- 官方**从不写文字方向词**，方向长在图里；任何 front/side/back 词都会压过姿势。
  别在角色迁移/序列帧替换里加方向词兜底。

`presets.build(..., pixelate=False)` 时用。别的档（anime/portrait/wuxia）
本来就没像素词，不受影响。

### ② alpha 被硬切（`generate.py::_postprocess`）★ 最直接
透明底起雾时一律 `_harden_alpha(240)` 把 alpha 砍成 0/255，1~2px 的抗锯齿
过渡整条消失。**像素画要硬边（是风格），插画不要。**
→ 按档位分级：`hard_edge = pixel>1 or palette>0`；硬边档仍 `_harden_alpha`，
插画档走 `sanitize_alpha`（只清 <16 / >240）。

### ③ 形态学开运算（同处）
`despeckle(denoise_iters=1)` 的 3×3 腐蚀→膨胀会削掉轮廓 <3px 的突起
（发丝、挂饰、裙摆细边）。
→ `denoise_iters` 只在像素化档生效；插画档仍做面积过滤（清碎屑/印章）。

### 记住
- **「像素感」不一定是 pixelate 造成的**，alpha 二值化 + 压抗锯齿同样是元凶，
  而且更隐蔽（数值上看不出"像素化"）。
- `clean_iso` 本来就有 `pixel>1 or palette` 前置条件，不像素化时不会跑。
- 新增 `tests/test_paint_path.py` 钉住：插画档保留过渡 alpha / 像素档仍硬切 /
  插画档不削细须 / 扣图节点照旧抠。

### 两个踩过的坑（都会再犯，记下来）
1. **别用 `opacity` 做"低调按钮"** —— 整个按钮连图标带边框一起半透明，
   在近黑画布上等于隐形（实测 0.45 完全看不见）。要用实心底 + 灰白边框。
2. **`.mini` 是 28×28 的图标按钮**（给 ✕ / ⤢ 单字符用）。往里塞"完成"两个字
   会竖排换行并溢出边框。文字按钮必须用自己的类（`.pzoom-done`）。
3. 数字框用 `flex-grow` 比例分配会被压到 30px（768 直接看不见），
   要 `flex: 0 0 52px` 固定住，剩余空间全给尺寸下拉。
