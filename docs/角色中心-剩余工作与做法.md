> 换成完整版时要处理：区域的 `max_pool2d` 膨胀 + `avg_pool2d` 羽化，

### 官方怎么做的

`VNCCS_EmotionsGenerator`（`character_generator.py:3367`）；
任务编排在 `emotion_generator_v2.py:675-761`；
QI2 分支是 `_run_qi2_emotion_crop_generation`（`character_generator.py:1591`）。

**管线**：YOLO 找脸框 → 裁切 → pad 到 32 的倍数 → 放大 → 生图 → 羽化贴回原图
→（必要时）局部重抠 → 落盘。

| `bbox_threshold` | **0.5**（Step3 专用；Step1/2 是 0.1） | `:1604` |
| `bbox_dilation` | **50**（Step3；Step1/2 是 10） | `:1612` |

**可以直接删掉不管的参数**：`guide_size`、`guide_size_for`、`max_size`、

### 关键算法（纯 torch / 纯几何，**零模型**，可直接抄）

| 函数 | 位置 | 做什么 |
|---|---|---|
| `_pad_image_to_square_multiple` | `:1571-1589` | 边长 `ceil(max(w,h)/32)*32`，**pad 用 `F.pad(..., mode="replicate")`**（不是 0 也不是 127） |
| `_crop_feather_mask` | `:1516-1530` | 边缘斜坡 mask：`min(到上下边距离, 到左右边距离)/feather`，clamp(0,1) |
| `_paste_crop_direct` | `:1483-1514` | `(1-mask)*原区域 + mask*patch`，通道只到 `patch.shape[-1]`（**alpha 不被混合**） |
| `_expanded_detailer_region` | `:3683-3705` | `max_pool2d` 膨胀（`matte_expand_radius=8`）+ `avg_pool2d` 羽化（`matte_feather_radius=4`），`maximum(mask, softened)` 只向外软化 |
| `_merge_emotion_rgba` | `:3707-3748` | 预乘空间 lerp：`alpha=lerp(old,new,w)`、`premult=lerp(orig*old_a, keyed*new_a, w)`、`rgb=premult/alpha` |
| `_face_prefix_from_sprite_prefix` | `:3982-3991` | `sprite_` → `face_`，用于 `Faces/` 镜像目录 |

**坐标映射（贴回时别搞错）**：裁的是 `crop_region=(x1,y1,x2,y2)`；
pad 后 `aligned_h = crop_h + top + bottom`；贴回前把 pad 反向切掉
`paste_crop[:, top:aligned_h-bottom, left:aligned_w-right, :]`（`:1670-1675`）。

## 5. T3：AI 向导（一句话造角色）

### 官方怎么做的

`character_creator_v2.py:1740-1869`。纯文本，**不需要 mmproj**（`require_mmproj=False`，`:409`）。

```python
# :1832-1839
```

`configure_qwen_text_chat`（`qwen_vl.py:53-64`，完整代码）：

```python
def configure_qwen_text_chat(llm):
    from llama_cpp.llama_chat_format import Jinja2ChatFormatter
    template = llm.metadata.get("tokenizer.chat_template")
    if not template:
        raise RuntimeError("Qwen3.5 GGUF is missing its chat template.")
    llm.chat_handler = Jinja2ChatFormatter(
        template="{% set enable_thinking = false %}" + template,
        eos_token="<|im_end|>", bos_token="",
    ).to_chat_handler()
```

即：**从 GGUF metadata 读 chat template，头部拼 `{% set enable_thinking = false %}`**。

system prompt（`:1775-1779`）：
```
You are a professional anime/game character designer. Convert broad character ideas into concise structured character fields. Output valid JSON only.
```

user prompt（`:1780-1829`）：`Create a character from this abstract idea:\n{user_description}`
+ **注入标签白名单**（`json.dumps(tag_options)`，从 `CHARACTER_PRESETS["tags"]` 抽
race/skin_color/hair/eyes/face/body/additional_details，`_extract_character_tag_options:412-435`）
+ `SKIN_COLOR_OPTIONS`（`:438`）+ 9 条 Rules + JSON 示例。

采样：`max_tokens=900, temperature=0.3`（`:1841-1848`）。

### 解析（三级降级，`parse_wizard_json` `qwen_vl.py:89-118`）

1. `json_repair.loads(content)`（需 `pip install json_repair`；**官方 requirements 里有**）
2. 结果是 list → 取 `data[0]`
3. 剥 ```json 代码块 → 裸 ``` → `re.search(r"\{.*\}", ..., re.DOTALL)`
4. 仍非 dict → `None`

### 后端后处理（值得照搬，能明显提升质量）

`postprocess_character_wizard_result`（`:588-604`）：
- `_normalize_wizard_race`（`:544-559`）：踢掉 `human/person/man/woman/boy/girl`
  和 `afro/african/black/student`（这些**不许进 race**），只留物种 tag；
  全空且有人类线索则回落 `"human"`。
- `skin_color`：用正则从**用户原话**反推并**覆盖模型输出**（`:527-541`）；
  原话没肤色线索就直接置空。
- `_normalize_wizard_body`（`:562-585`）：剔 `body/unknown/none/n/a`；
  **sex==female 且没提胸围时强制追加 `small_breasts`**。

## 6. T4：换装（Clothes Designer + Clothes Generator）

### 官方怎么做的

Clothes Designer（`clothes_designer.py:318`）本质是**图生图改图**：
拿 `Naked`（或 `Original`）底图 + 服装描述 → 出一张换装后的图 → 只进缓存
`cache/preview_<costume>.png`。

Clothes Generator（`character_generator.py:3184`）接 Designer 的输出当底图，
再批量出各姿势精灵，落到 `Sprites/<costume>/Neutral/sprite_pose_%04d.png`。

**所以不是"只存描述下次拼 prompt"** —— 描述是先变成一张换装底图的。

### prompt（原样抄，`clothes_designer.py:413-448`）

```python
# generate 模式 (:429-439)
positive_prompt = f"Dress the character:\n{clothes_desc}\n{background_prompt}"
negative_prompt = "bad quality, worst quality, (naked, nude, nipple, penis, vagina:2.0)"

# clone 模式 (:424)
positive_prompt = "Dress character to clothes from image 2\n" + background_prompt
```

`clothes_desc` = 五个字段（top/bottom/head/shoes/face）非空值用 `\n` 拼起来。
（第六个 `negative_prompt` 属 `COSTUME_TEXT_FIELDS` 可存，但**官方 UI 没暴露、
prompt 里也没用**，`clothes_designer.py:440` 是硬编码的。）

背景段 `_clothes_background_prompt`（`:124-135`）：
- Transparent → `Transparent background with alpha channel.`
- Blue → `flat uniform pure blue background, exact RGB (0, 0, 255), hex #0000FF, no purple, no violet, no gradient`
- Green → `flat uniform pure green background, exact RGB (0, 255, 0), hex #00FF00, no gradient`

### Clothes Core LoRA

`VNCCS_QI2_ClothesCoreV2.6.safetensors`（已装），**strength 1.0，clip 强度 0，
没有触发词**（`clothes_designer.py:286,301,711-716`）。

### 采样

QI2：`steps=25, cfg=3.0`（`:555-556`）；`target_size` 默认 1024（`:163`）。

### Prompt Enhancement（可选）

`_rewrite_qi2_clothes_prompt`（`:138-159`）：用 `qi2_edit_prompt_rewriter.txt`
（已入库）改写，**改写完要把 constraints 追回**（`return f"{rewritten}\n{constraints}"`）。
不装 LLM 也能跑 —— 关掉 `qi2_prompt_enhancement` 即可，原样 prompt 已可用。

### 我们这边怎么做

1. `construct_prompt()` 照抄 → 加进 `workflows/charactergen.py`。
2. `/characters/{name}/generate` 的 w2 路径已经能图生图，接上服装 prompt 即可；
   底图取 `Naked`/`Original` 的最新一张（官方 `get_latest_sprite_path`，
   `clothes_designer.py:191`，**要跳过 V1/V2 归档目录**）。
3. 换装后的图作为新服装的底图存进 `Sprites/<costume>/neutral/`。
4. T6（服装 AI 向导）可以并进来：prompt 原文见 `clothes_designer.py:920-955`
   （输出 `top/bottom/shoes/head/face` 五个 key，`face` 只放眼镜/口罩这类**可穿戴物**，
   不放表情/妆容），`max_tokens=900, temperature=0.35`。

### 验证

- prompt 字符串逐字对比官方常量（写死断言，改一个字就红）。
- 底图选择：有 `Naked` 用 `Naked`，没有用 `Original`，归档目录不算。

## 7. T5：多姿势生成

### 官方怎么做的

`_run_pose_generation`（`character_generator.py:2108`），QI2 分支 `:2186-2223`。

**prompt 原文**（`:2208-2213`）：
```
Replace the pose of <image 2> with the pose of <image 1>. Keep the character of <image 2>. {user_prompt}
```
`image1 = pose`（姿势引导图）、`image2 = character`（角色底图）。
**不传 negative_prompt**。

其他要点：
- **QI2 是串行 for 循环**，不是 batch（`:2205`），每张独立 encode→sample→decode。
- **种子：所有姿势用同一个 pipe 种子**（`pose_sampler.inherit_pipe=True`，`:826`）
  —— 这是姿势一致性的关键。
- 默认采样 `steps 20 / cfg 1.0 / euler / simple / denoise 1.0`（`:825-833`）。
- Pose LoRA：`VNCCS_QI2_PoseStudioV1.1.safetensors`，strength 1.0（`:1797,1853,1871`）。
  我们有 `vnccs_pose_v2.safetensors`（同物的老版本），够用；想要官方最新版
  可以用 `tools/fetch_vnccs_weights.py` 的清单加一项。
- 产物：`_save_final_sprites`（`:2740-2764`），`sprite_pose_%04d.png`，从 1 开始，
  走 `staged_image_batch`（旧图整批进 `V1`）。
  这一套**我们已经实现了**（`characters.publish_image` + `staged_image_batch`）。

### 我们这边怎么做

1. 姿势引导图从哪来：用我们已有的**人偶姿势节点**（PoseStudio iframe）导出的人偶图，
   或官方姿势库（191 个）。
2. 串行循环调我们的图生图接口，同一 seed。
3. 一次出一整批时用 `staged_image_batch`（旧版进 V1）—— 逐张发布用
   `publish_image`（追加，不归档）。**别搞混**（这个坑踩过一次）。

## 9. 几个反复踩过的坑（做之前先看）

1. **LoRA 格式**：`available_loras()` 只认 diffusers 原生（`transformer.` 前缀）。
   ComfyUI 格式挂上去**静默不生效**（什么都不报，只是"出图跟没挂一样"）。
   新增 LoRA 后跑一遍格式检查，不合规就 `tools/convert_lora.py`。
   三种 ComfyUI 变体都能转（含无前缀 + `.lora_A.default`）。
2. **逐张发布 vs 整批发布**：逐张是**追加**（`sprite_pose_0001..N`）；
   `staged_image_batch` 是整批替换 + 旧版进 `V1`，只给"一次出一整批"用。
   搞混会把先发的图挤进 V1。
3. **角色目录必须在 `assets/` 下** —— 预览图走 `/files/`，那个端点只服务 assets。
   挪走就是满屏裂图（有测试钉着）。
4. **目录大小写**：官方是 `Sprites/Original/Neutral/`（首字母大写），
   我们归档用小写 `neutral`。枚举时**两种都要认**，否则别人的角色库拷进来翻不出图。
5. **Prompt Enhancement 是增强不是依赖**：失败一律退回未扩写 prompt，不阻断出图。
6. **PE 的显存代价还没解决**：要常驻 GPU 跑自回归解码，而管线是"编码完就挪走"
   （`engine.py:439`，两块 fp8 常驻 15.5GB 已压线）。24GB 上跟 transformer 抢。
   待办：量真实显存/耗时，再定默认值与"PE 完立刻卸载"策略。
7. **llama-cpp 装错 fork 的症状**是 `ImportError: Qwen35ChatHandler`，
   很容易被误判成"我们代码写错了"。
8. **下载**：直连 huggingface.co 是 502；`hf-mirror.com` 通但 1.2MB/s；
   `127.0.0.1:7897` 代理 11.7MB/s。脚本有 `--proxy` / `--endpoint`。
